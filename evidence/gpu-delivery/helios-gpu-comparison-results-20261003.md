Each row has four balanced sequential repetitions, with excluded warmups and every-frame quality/cadence qualification. Whole export clocks include fresh adapter startup, scene/font setup, raster, transfer/conversion, encoding, drain, mux and write. They are not pure GPU throughput. Quality/profiling/builds are outside the clocks. Delivered clocks add one full decode and supervisor cleanup.

TextGrid is 3,334 labels, 1920×1080, 300 frames at 30/1 fps, no audio, pinned DM Sans. The matched software lane uses identical x264 medium/CRF11/two-thread settings and explicit sRGB-to-limited-BT.709 conversion. Both native software paths explicitly download raw GPU frames; Remotion's actual Chromium GPU raster is followed by PNG/CDP readback. All four pairs favor Helios export time. Delivered medians are H 28.142 s, F 32.703 s, R 48.610 s.

The separate TextGrid hardware lane uses H 100 Mbps/BT.709 GPU conversion versus F 180 Mbps/BT.601 attachments and opaque encoder conversion, with different product concurrency. fframes exports are shorter in all four pairs. Delivered medians are H 7.929 s and F 7.892 s; a 0.46% median difference is not a meaningful delivered-time winner. This lane cannot isolate GPU raster or color conversion performance. Worst qualified frame values are retained in the reviewed summaries. H's hardware reference is directly NV12 byte-bound; F's hardware proxy is actual BGRA rendered into the hardware target followed by separately disclosed FFmpeg conversion. Old invalid H color and Remotion black-frame references, failed screens and original clocks remain retained.

The 4K row is a separate documented-scene replication: 99,000 circles and 1,000 digits, 20 panels, 3840×2160, source frames 3–302, 300 at 30/1 fps. Both use serial raster, required hardware H.264, shared requested/configured 300 Mbps, pool 3, GOP 30, GPU sRGB-to-limited-BT.709 NV12 and copy mux. H is the retained TypeScript Canvas API with bounded binary transport/Skia 0.91. F is optimized SVG/Skia 0.153.3 Metal HardwareFrames with one disclosed extra GPU texture copy into the common converter. It is a task adapter, not the original fframes MaxPerformance production pipeline.
