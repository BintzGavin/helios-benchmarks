# 4K circle comparison protocol

This is a separately labeled matched-converter adapter lane on Apple M3 Pro, not the upstream fframes production pipeline or the separate M5 Max claim. The current public fframes scene is replicated: 99,000 circles, 1,000 digits, 20 panels, nonuniform 1000-square viewBox mapping to 3840×2160, source frames 3–302, 300 frames at 30/1 fps, no audio, pinned 72,000-byte DM Sans. Circles precede text. Source equations, command count/order, transforms and selected frames have independent golden checks. First-frame lossless images were visually reviewed; renderer antialiasing/text differences are quantified separately and cross-engine pixel identity is not asserted.

H uses the retained TypeScript Canvas API, direct bounded binary recording, native Skia 0.91/Metal and required hardware VideoToolbox H.264. F uses the public optimized SVG scene, Skia 0.153.3 actual Metal HardwareFrames, one disclosed GPU BGRA-to-private-RGBA texture copy, then the same explicit GPU sRGB-to-BT.709-limited NV12 conversion and required hardware encoder. Both raster pipelines are serial, use encoder pool capacity 3, GOP 30, requested/configured 300 Mbps, and copy-mux to MP4. F's original MaxPerformance multi-context/BT.601 attachment pipeline remains separate; failed 8/200/500 Mbps quality screens are retained. The adapter is not presented as an upstream production optimization.

300 Mbps is the lowest tested passing shared setting, after the 200 Mbps Helios screen failed and both 500 Mbps common-converter screens passed. It is not a global rate optimum. Shared 300 Mbps screens must pass every frame: SSIM-Y ≥ .995 and PSNR Y/U/V ≥ 40/35/35 dB, exact decoded dimensions/count/PTS n/30, limited BT.709 color metadata and observed maximum decoded keyframe spacing ≤ 30. No threshold changed after observing candidates. Every timed run is gated again; a failure stops the series and cannot be promoted by a config flag.

Own references are FFV1 yuv420p from actual GPU NV12. The source input is explicitly tagged before FFmpeg format conversion. Independently splitting direct NV12 Y bytes and even/odd UV into planar Y/U/V without arithmetic matches all 300 decoded reference frame hashes. H's original, budget and binary helpers independently reproduce all fixed reference hashes. F's final reference is bound to its same source stream, while separate F raster renders vary on a small number of pixels: one comparison changed five frame hashes; another changed 290 bytes in two frames (frame 0: 289 bytes, max delta 47; frame 220: one byte, delta 4). The cause is unresolved. Old references, failed bindings and candidate clocks remain retained; no metadata-only or exact independent-raster-repeatability claim is made.

Actual GPU evidence is separate from timing. Independent interposer probes include NV12-map and RGBA-download positive controls. The uncaptured H binary hardware probe observes GPU conversion/callback completion with no hooked raw downloads; F observes GPU import/conversion/callback completion and no hooked raw downloads. Metal capture snapshots cause additional IOSurface locks and are separately excluded. Unknown buffer accesses, system pointer queries and opaque/unhooked encoder/driver transfers mean `zeroCopyProved=false`. CPU geometry/font uploads, F's extra GPU copy and compressed-packet CPU output are disclosed.

Before timing, source, helper, adapter, converter, runtime, reference, screen and profiling receipts are SHA-256 bound. No rebuild, source mutation, competing engine, profiler, capture or other heavy implementation work runs during the window. One excluded full warmup per engine precedes four pairs ordered H/F, F/H, F/H, H/F. Export starts before spawning the fresh adapter and includes font/media setup, scene generation/transport, raster, conversion, encoding, final drain, mux and write. Delivered time includes one full software decode and supervisor cleanup; fidelity, color/GOP/ledger checks and storage maintenance are outside both clocks. Original clocks are never reconstructed from later validation.

Every run retains MP4, adapter receipt, exact argv, stdout/stderr, SHA-256, resource samples and every-frame quality evidence. Task-owned elementary mux intermediates may be reclaimed only after proving byte-exact reconstruction from retained MP4 NAL payloads plus saved original Annex-B prefix metadata. Byte-identical task videos may be hardlinked after SHA-256 equality, retaining every path and byte. Neither changes the candidate or its original clock.

The public M5 Max 7.225018333-second measurement is a separate single run on different hardware at 8 Mbps with different timing boundaries. Its recorded renderer revision does not contain the measured circle program, and its uncommitted measured-source hashes cannot be recovered exactly. This run supports a same-Mac, documented-scene adapter comparison; it cannot establish a win over that published number. TextGrid results and hardware/product/software lanes are never pooled with this scene.
