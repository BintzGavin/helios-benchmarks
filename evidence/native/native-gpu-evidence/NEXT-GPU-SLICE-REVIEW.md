## 2. Bounded encoder-buffer overlap, separate from circle support

Current `helios_encode` converts one reusable NV12 IOSurface, waits for the GPU, submits to VideoToolbox, calls CompleteFrames for every frame and waits for its callback. This guarantees serial reuse but prevents encoder/raster overlap. Do not remove conversion completion: one private RGBA raster texture remains safe only because conversion finishes before the next raster modifies it on the same Metal queue.

Recommended first overlap scope: retain the existing raster/conversion fence; acquire each encoder input from VideoToolbox's pixel-buffer pool with an allocation threshold of three; submit ordered PTS without a per-frame CompleteFrames; release application-owned buffer/plane wrappers once safe while VideoToolbox retains its input. Obtain recycled buffers through CoreVideo's pool rather than manually overwriting a slot merely because a callback fired. Retention may outlive callback entry. If allocation reaches the threshold, drain the oldest submitted PTS once and retry allocation; fail explicitly on a second failure, never spin/poll or grow the pool. Final EOF drains all frames exactly once and verifies every submitted frame received exactly one successful callback before writing the receipt.

Use per-frame tickets, bounded accounting and synchronized callback failure/output state. A callback may execute before EncodeFrame returns, so install ticket/accounting before submission and never hold a callback mutex across EncodeFrame. Keep compressed-packet output ordered; fail on duplicate/unexpected frame IDs, dropped frames, encode errors or timeouts. Cancellation drains/invalidate/releases before State and tickets die. Separate reference mode keeps synchronous single-buffer behavior. Pool/reference binding must identify every IOSurface, plane, GPU conversion completion, encoder submit/callback and pool reacquisition. Callback completion alone is not a total zero-copy proof.

Acceptance: injected synchronous/delayed/out-of-order/drop/error callbacks exercise ticket lifetime and bounded accounting; threshold pressure and cancellation cannot deadlock; all300 decoded frames/PTS/colors and existing per-frame quality floors pass; direct NV12 oracle matches all300 frames; actual Metal/interposer profile plus download positive controls; no application raw readback; zeroCopyProved remains false. Benchmark against the newly frozen circle-capable baseline with identical scene, color, GOP, bitrate, source frame range and clocks. Do not infer gains from excluded TextGrid screens (~5.15s fframes180Mbps vs~6.35s Helios100Mbps).

Own product write set for this separate slice: native/metal.mm, native/src/main.rs final-drain FFI, native tests/failure harness, GPU-SPEC/profiling protocol. Preserve all previous measurements; exact source/build/helper bindings change with the implementation.
